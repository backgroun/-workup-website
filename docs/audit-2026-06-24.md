## 1. 보안 (최우선) — 직접 재검증 완료

### S1. 🔴 회원 개인정보(PII) 무인증 노출
- 위치: `app/api/admin/members/route.ts:10-39`
- 증상: `GET` 핸들러에 인증 체크가 전혀 없음. (같은 파일 `POST`는 line 42에서 `checkAuth()` 호출.)
- 원인: `middleware.ts`가 인증을 강제하지 않고(헤더만 설정), API 라우트가 각자 인증을 호출하는 구조인데 GET이 누락됨.
- 영향: 누구나 `/api/admin/members` 직접 호출 → 전 회원의 이름·이메일·전화번호·메모·등급을 검색·덤프 가능. `?search=`, `?searchType=email` 등 쿼리도 그대로 동작. **개인정보보호법 직결.**
- 수정 방안:
  ```ts
  export async function GET(req: Request) {
    if (!(await checkAuth())) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
    // ...기존 로직
  }
  ```
- 동일 결함(읽기 GET 인증 누락) 일괄 점검 대상:
  - `app/api/admin/brands/route.ts:11`
  - `app/api/admin/manufacturers/route.ts:11`
  - `app/api/admin/catalog/route.ts:18`
  - `app/api/admin/hero-slides/route.ts:10`
  - `app/api/admin/analytics/pixels/route.ts:10`

### S2. 🔴 회원 세션 쿠키 위조 → 임의 회원 사칭
- 위치: `app/api/member/me/route.ts:8,15` · `app/api/member/login/route.ts:37` · `app/api/register/route.ts:47`
- 증상: 회원 세션이 `wu-member = <회원 id 원문>` 형태(서명/HMAC 없음). `me` 라우트가 이 쿠키 값으로 그대로 DB 조회.
- 영향: 쿠키 값을 임의 id로 설정하면 비밀번호 없이 그 회원을 사칭하여 이름·이메일·등급 조회 가능.
- 수정 방안: 서명된 토큰(HMAC/JWT) 또는 서버 세션 테이블 도입. 최소 조치로 `wu-member`에 `HMAC(id, secret)` 서명을 붙여 검증.

### S3. 🔴 공개 API가 내부 단가(공급가·소비자가) 노출
- 위치: `app/api/products/route.ts:11` (`select("*")`) → `lib/supabase-server.ts:28-29` `mapFromDb`가 `consumerPrice`·`supplyPrice` 포함 반환
- 증상: 무인증 공개 엔드포인트가 모든 컬럼을 반환. `supply_price`(공급가)는 내부 단가.
- 영향: 일반 방문자/경쟁사가 도·소매 단가를 그대로 열람 가능.
- 수정 방안: 공개 응답 전용 매퍼(화이트리스트)로 `supplyPrice`(필요 시 `consumerPrice`도) 제외. 관리자 API(`/api/admin/products`)는 현행 유지.

### S4. 🔴 관리자 인증이 고정 공유 비밀 + 하드코딩 폴백
- 위치: `app/api/auth/login/route.ts:7-9`, `app/admin/layout.tsx:8`, 전체 admin 라우트의 `checkAuth()`
- 증상: 환경변수 미설정 시 `admin@workup.kr` / `workup2026` / 토큰 `wu-session-ok`로 동작. 쿠키 값이 모든 관리자가 공유하는 고정 문자열 하나라 만료·회전·개별 무효화 불가.
- 양호한 점: 쿠키에 `httpOnly`, `secure`(prod), `sameSite=lax` 적용됨.
- 수정 방안:
  1. 프로덕션에 `AUTH_EMAIL`/`AUTH_PASSWORD`/`AUTH_TOKEN` 환경변수가 실제 설정돼 있는지 즉시 확인.
  2. 폴백 제거(미설정 시 로그인 거부)로 기본 크리덴셜 유출 방지.
  3. (선택) 토큰을 무작위 1회성 값으로 발급하고 만료 적용.

### S4-보강. 비밀번호 해시·기타
- `app/api/register/route.ts:6` · `member/login/route.ts:6` — `SHA256(pw + 전역 고정 salt)`. 사용자별 솔트 없음 + 고속 해시. → `bcrypt`/`argon2` 권장.
- `app/api/route-distance/route.ts:14-34` — 공개 POST가 `destinations` 배열 길이 제한·입력검증·try/catch 없음. 거대한 배열로 Kakao Mobility API 무제한 병렬 호출 → 키 남용/비용 폭증/DoS 가능. 길이 상한(예: 50) + body 파싱 가드 필요.
- `app/api/inquiries/route.ts` · `register` · `member/login` — 레이트리밋/CAPTCHA/허니팟 없음. 문의(핵심 KPI) 스팸 오염, 봇 가입, 로그인 무차별 대입 가능. 이메일 형식 검증도 없음.
- 매스 어사인먼트: `hero-slides/[id]/route.ts:17`, `catalog/[id]/route.ts:18`, `brand-catalogs/[id]/route.ts:25`, `catalog/route.ts:42` 등이 원시 `body`를 그대로 `insert/update`. 필드 화이트리스트 권장.

## 3. 기능 버그

### B1. 🟡 ProductForm 저장 시 필드 소실

- 위치: `app/api/admin/products/[id]/route.ts:18-23` + `mapToDb`가 모든 필드 기본값 포함
